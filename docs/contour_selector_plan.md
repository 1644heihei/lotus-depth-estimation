# 輪郭選別器 — 実装計画

**実施済。結果は [`contour_selector_results.md`](contour_selector_results.md) ── 生の BF1 増分 +12.49%、成功基準 +10% を超えた。**

作成: 2026-09-23
前提: [`marigold_v2_transfer_results.md`](marigold_v2_transfer_results.md) §4

---

## 0. 解く問題

SAM の輪郭画素のうち **79.8% は深度の段差が無い場所**にある。
そこで「±2px の帯を捨てて埋め直す」操作をすれば滑らかな面を壊すだけで、
これが鋭化が Marigold V2 で −1.90% になる原因である。

位置精度は足りている（真の段差から最寄りの輪郭まで中央値 1.00px）。
**必要なのは「この輪郭画素に深度の段差があるか」の判定器である。**

| | 生の BF1 増分 |
|---|---:|
| 選別なし | **−1.90%** |
| オラクル選別（GT で 1px 以内に絞る、位置精度は同じ） | **+43.39%** |

45pt の幅がある。**そこそこの選別器でも正に届く余地が広い。**

---

## 1. 疎さの交絡 — 既に排除されている（改訂）

初版は「オラクル選別が輪郭を 4.0% に減らすので、選別の質ではなく疎であること自体が
効いているのではないか」を最優先の対照に据えた。**これは既存の測定で答えが出ていた。**

移設対照 `yolo_ctrl` の実装は `np.roll(cont, (dy, dx))` であり、
**画素数も形状もそのままに場所だけを動かす**。つまり「同じ疎さ、違う場所」である。

| | 生 | 移設対照（同じ疎さ・違う場所） |
|---|---:|---:|
| SAM 全輪郭 | −1.90% | −6.22% |
| **オラクル選別 k=1px（4.0%）** | **+43.39%** | **−0.50%** |

4.0% の疎さのまま場所を動かすと −0.50% にしかならない。
**効果は疎さではなく「正しい場所にあること」から来ている。**

### それでも要る対照 — 無技能の選別器

排除されたのは「疎さそのもの」であって、**「SAM 輪郭の上にランダムに 4% 残した場合」**
ではない。移設対照は輪郭を SAM 輪郭から**外す**ので真の段差に当たる率がほぼ 0 になるが、
ランダム部分集合は SAM 輪郭上に留まるので約 20% は当たる。

これは**技能ゼロの選別器が到達する床**であり、学習した選別器はこれを明確に上回る必要がある。
全 Phase で残存率を揃えて並走させる。

### 実施結果（2026-09-23）— Phase 0a 通過

| 輪郭源 | 残存率 | BF1 | 生 | 移設対照 |
|---|---:|---:|---:|---:|
| SAM 全輪郭 | 100% | 0.0867 | −1.90% | −6.22% |
| 画素ランダム | 3.95% | 0.0704 | **−20.35%** | −2.23% |
| ブロックランダム | 4.05% | 0.0877 | −1.48% | −0.31% |
| **オラクル選別** | 3.95% | **0.1267** | **+43.39%** | −0.50% |

**同じ 4% でも、正しい 4% と適当な 4% で 44.9pt 違う。**
中止条件（ランダムで +43% 近く）には該当せず、**選別器に投資する根拠が確定した。**

## 1.5 操作は輪郭の連結性を要求する（Phase 0a の副産物）

予測は「画素ランダムは 0% 付近、ブロックはそれよりわずかに良い」だった。
**順序は合ったが、画素ランダムの −20.35% は想定外**である。輪郭を全部使うより 10 倍悪い。

理由は操作の機構にある。孤立した輪郭画素は ±2px の小さな円盤を捨てて周囲から埋め直すだけで、
**障壁として機能しない**。`propagate_labels` が 2 つの面を分離できないためラベルが 1 つのままになり、
small disc をぼかすだけになる。それが数千個あれば損害だけが積み上がる。

### 設計制約

**選別器は空間的に連続した出力を出さなければならない。**
画素ごとに独立に判定する分類器は、まだらな出力で −20% 側に落ちる危険がある。対処は 3 つ:

- CNN（構造上なめらか）を先に使う
- 勾配ブースティングの出力に形態素処理を掛ける
- 一定サイズ未満の連結成分を捨てる

> **訂正（実測により撤回）.** この「連続性の制約」は成立しない。
> NYUv2 のオラクル選別（適合率 100%、生の BF1 **+43.39%**）の出力自体が、
> 学習した選別器と同程度に断片的である（連結成分の長さ 中央値 11.3px、67.8% が 20px 未満）。
> 断片的でも +43% 出る以上、画素ランダムの −20.35% は構造の欠如ではなく
> **適合率 7.6% という低さ**で説明される。
> 実際、連結成分の最小サイズ下限を入れる後処理は測定で **3.9pt 悪化**した
> （+8.61% 対 +12.49%、`docs/contour_selector_results.md` §4）。畳み込みだけで十分になめらかである。
> 下の「出力の連続性」行と §4 の後処理方針も同じ理由で無効。

### 選別は画素単位でしか実現できない

連結成分単位の対照を作ろうとして失敗した。**SAM の全体分割輪郭は巨大な 1 つの連結成分**を成し、
成分を 1 つ選ぶだけで残存率が **55.5%** に跳ねる。輪郭を小さな塊に分けることはできない。
したがって「どの輪郭成分を採るか」という定式化は成立せず、画素単位の判定が必須である。

## 2. 信号は存在するか（Phase 0）

選別器を作る前に、**判定に使える情報がそもそも画像側にあるか**を測る。

各輪郭画素について、ラベルを「GT の深度不連続から 1px 以内か」とし、
候補特徴量ごとに AUC を測る。学習は不要、既存の NYUv2 654 枚で済む。

### 候補特徴量

| 特徴 | 根拠 |
|---|---|
| 輪郭法線方向の**予測深度の勾配** | モデルが既に段差を（鈍くとも）認識していれば勾配が立つ |
| 同・RGB の勾配 | 色の境界は深度境界と相関する（ただし RGB エッジ単独は失敗済み） |
| 予測深度の局所分散（帯の両側） | 段差があれば両側の分布が分かれる |
| 輪郭の長さ・閉曲線かどうか | 物体の外形は段差になりやすく、内部の模様はなりにくい |
| 近傍の輪郭密度 | 密集は模様、孤立は物体境界 |
| SAM のマスク面積 | 小さすぎるマスクは模様の可能性 |

### ゲート（事前）

| 結果 | 行動 |
|---|---|
| 単独で AUC ≥ 0.65、または組み合わせで ≥ 0.75 | Phase 1 へ |
| すべて 0.6 未満 | **情報が無い。** 画像側の信号だけでは判定できないので、方針を再考 |

### 実施結果（2026-09-23）— 形式上は通過、しかしゲートが誤り

`eval_contour_feature_auc.py`、NYUv2 200 枚、輪郭画素 200 万、正例率 5.8%。

| feature | AUC |
|---|---:|
| **dgrad_max5**（予測深度の勾配・5×5 最大） | **0.8759** |
| drange9（予測深度の局所レンジ・9×9） | 0.8698 |
| drange5 | 0.8660 |
| dstd5 | 0.8642 |
| dgrad | 0.8012 |
| rgrad（RGB 勾配） | 0.5685 |
| cdens15（輪郭密度） | 0.5345 |
| 組み合わせ（別フレームで評価） | 0.8732 |

**信号は予測深度そのものにある。** 上位 4 つはすべてモデル自身の予測深度から作った特徴で、
**モデルは段差の位置を既に知っていて鈍く描いているだけ**だということを意味する。

**RGB 勾配は 0.5685 でほぼ無意味。**
[`rgb_edge_route_closure.md`](rgb_edge_route_closure.md) で RGB エッジ経路が全設定で悪化した
過去の結果と整合する。色の境界では模様と深度境界を区別できない。

**輪郭密度も 0.5345 で無意味。** 「密集は模様、孤立は物体境界」という仮説は外れた。

**組み合わせ（0.8732）が最良の単独（0.8759）を超えない。** 深度由来の特徴が互いに強く
相関しており、同じものを測っている。線形結合に上積みが無い。

**注意**: `load_or_build_masks` はキャッシュが無いと YOLO へフォールバックするが、
鋭化スクリプトは `yolo=None` を渡すので `AttributeError` で止まる。
**黙って飛ばされはしない**ので、train 側の輪郭は事前生成すれば足りる。

**注意**: SAM の `stability_score` と `predicted_iou` は現行キャッシュ
（`packed` + `n` のみ）に保存されていない。使うなら再生成が要る。
Phase 0 では使わず、有望なら後で足す。

## 2.5 AUC はゲートに使えない — 必要なのは適合率（2026-09-23）

AUC 0.876 を得た `dgrad_max5` で**学習ゼロの閾値選別器**を作り、端から端まで測った。
オラクルと同じ枚数を残す閾値を各フレームで取り、形態素処理（連結成分 20px 未満を除去）の
有無で 2 通り。

| 選別 | 残存 | BF1 | 生 | 移設対照 |
|---|---:|---:|---:|---:|
| 選別なし | 100% | 0.0867 | −1.90% | −6.22% |
| 画素ランダム | 3.95% | 0.0704 | −20.35% | −2.23% |
| ブロックランダム | 4.05% | 0.0877 | −1.48% | −0.31% |
| **閾値 dgrad_max5** | 6.58% | 0.0865 | **−2.07%** | −0.47% |
| 閾値 ＋ 小成分除去 | 6.04% | 0.0867 | **−2.57%** | −0.45% |
| オラクル (GT) | 3.95% | 0.1267 | **+43.39%** | −0.50% |

**AUC 0.876 は選別なし（−1.90%）より悪い結果しか生まなかった。**

### 適合率を測ると理由が分かる

| 選別 | 残存 | 適合率 | 再現率 | ベース比 |
|---|---:|---:|---:|---:|
| 閾値 raw | 6.56% | **34.6%** | 37.7% | 5.7× |
| 閾値 clean | 6.08% | 36.1% | 36.5% | 6.0× |
| 画素ランダム | 4.11% | 7.6% | 5.2% | 1.3× |
| オラクル | 6.03% | 100.0% | 100.0% | 16.6× |

（輪郭画素の正例率 = 6.03%）

### 適合率と BF1 は直線で結ばれる

両端 2 点（適合率 7.6% → −20.35%、100% → +43.39%）から引いた直線は

```
生の BF1 増分 ≈ 0.69 × (適合率 − 37.1%)
```

これで閾値選別器を予測すると **−1.73%**、実測 **−2.07%**。**0.3pt しか違わない。**

| 目標 | 必要な適合率 | ベース比 |
|---|---:|---:|
| 損益分岐（0%） | **37.1%** | 6.2× |
| **+10%（成功基準）** | **51.6%** | **8.6×** |
| +20% | 66.1% | 11.0× |

**閾値選別器の 34.6% は分岐点をわずかに下回る。**
学習器に求められるのは 5.7× → 8.6×、つまり**適合率を 50% 伸ばすこと**である。

### ゲートの誤りを記録する

事前に置いた「AUC ≥ 0.65 なら通過」は**誤った量を測っていた**。
正例率 6% の不均衡問題では、AUC が高くても上位数 % の適合率は別物である。

[`marigold_v2_transfer_results.md`](marigold_v2_transfer_results.md) §3.3 の
「正味 vs 生」に続いて、**事前基準が誤った量を測っていたのは 2 度目**である。
**今後のゲートは端から端までの量に直結する指標のみとする** ——
この場合は AUC ではなく「残存率を揃えた適合率」。

### 予測の記録

「AUC 0.876 なら端から端までは +5〜15%」と予測し、**−2.07% で大きく外した**。
AUC を適合率に換算せずに楽観したことが原因である。

## 3. 学習データ（Phase 1）

### 3.1 第一選択は NYUv2 train

| | 枚数 | シーン | test との重複 |
|---|---:|---:|---:|
| NYUv2 train | **795** | 249 | **0** |
| NYUv2 test | 654 | 215 | — |

シーン重複ゼロなので、**そのまま zero-shot に近い評価になる。**

必要な前処理は 2 つだけで、どちらも安い。

| | 内容 | 時間 |
|---|---|---|
| SAM auto48 輪郭 | test 654 枚と同じ設定で train 795 枚（実測 2.9 秒/枚） | **0.6 時間** |
| Marigold V2 予測 | 795 × 0.72 秒 | **10 分** |

輪郭画素は valid 内で **1 枚あたり 22,043**（実測）なので、**795 枚で約 1,750 万の教師ラベル**。
小さいモデルには十分である。

### 3.2 Hypersim は第二段階

`D:/lotus/data/hypersim_sam_seg/` に 59,543 枚の SAM マスクが既にあるが、
**生成方式が違う**（YOLO の bbox をプロンプトにしたもの。NYUv2 側は全体分割の automatic）。
分布が異なるので、そのまま学習データにすると転移しない恐れがある。

Hypersim を使うなら automatic モードで再生成が要り、加えて Marigold V2 の予測も要る
（59,543 × 0.72 秒 ＝ **11.9 時間**）。**Phase 2 が成功してから判断する。**

## 4. 選別器（Phase 2）

**§1.5 の制約により、どの方式でも出力の空間的連続性を確保すること。**
まだらな選別は全輪郭を使うより 10 倍悪い（−20.35% vs −1.90%）。

### 4.1 まず勾配ブースティング（ただし後処理必須）

Phase 0 の特徴量をそのまま使う。学習は数分。
特徴量の寄与が見え、失敗時に「情報が無い」のか「モデルが足りない」のかを切り分けられる。

**画素ごとに独立に判定するので、そのままではまだらになる。**
確率マップに形態素処理を掛け、小さな連結成分を落としてから鋭化に渡す。
この後処理の有無で両方測り、連続性の寄与を分離する。

### 4.2 CNN

入力 5ch（RGB 3 ＋ 予測深度 1 ＋ 輪郭マスク 1）、出力 1ch の確率。
損失は輪郭画素のみに掛ける（マスク付き BCE）。小さな U-Net で足りる見込み。

畳み込みは構造上なめらかな出力を出すので、**§1.5 の制約に対しては勾配ブースティングより有利**。
4.1 が後処理込みでも駄目なら、ここで切り分けがつく。

## 5. 評価（全 Phase 共通）

### 5.1 二段階で見る

| 段階 | 指標 |
|---|---|
| 選別器そのもの | precision / recall / AUC。オラクル選別との一致率 |
| **端から端まで** | 鋭化を通した **BF1**。移設対照 ＋ **同率ランダム対照** |

### 5.2 判定基準（着手前に固定）

**「生」がベースラインを上回ることを必須条件とする。**
[`marigold_v2_transfer_results.md`](marigold_v2_transfer_results.md) §3.3 で、
「正味」は生が正のときしか改善を追わないことが判明したため。

| 生の BF1 増分 | 判定 |
|---|---|
| ≥ +10% かつ 同率ランダム対照を 2 倍以上上回る | **成功。** 修論の主結果になる |
| +3〜10% | 部分的成功。閾値掃引と特徴量追加で伸ばす |
| ≤ 0% | **失敗。** 選別器の経路を閉じる |

選別器は確率を出すので、**閾値を掃引して BF1 の曲線を出す**。
残存率と BF1 の関係が、オラクルの 4.0% / +43.39% にどこまで近づくかを見る。

### 5.3 中間ゲートは適合率で見る（§2.5 の教訓）

端から端までを回す前に、**残存率を揃えた適合率**で足切りする。AUC は使わない。

| 適合率（残存率 ≈ 6%） | 予測される生の BF1 | 行動 |
|---:|---:|---|
| < 37% | 負 | その設定は捨てる |
| 37〜52% | 0 〜 +10% | 端から端までを回す |
| > 52% | +10% 以上 | **成功。** 端から端までで確認 |

換算式は `生 ≈ 0.69 × (適合率 − 37.1%)`。実測 3 点で 0.3pt の精度で当たっている。
参照点は閾値選別器の **34.6%**（学習ゼロ）で、**学習器はこれを超えなければ意味がない**。

## 7. 既知のリスク

| | 内容 |
|---|---|
| ~~疎であることの交絡~~ | **排除済み**（§1）。移設対照が同じ疎さで −0.50% |
| **循環** | オラクル選別は GT の深度不連続で選び、BF1 も GT の深度不連続で採点する。学習器は GT を見ないので循環しないが、**教師ラベルが評価指標と同じ定義**である点は論文に明記する |
| **出力の連続性** | §1.5。まだらな選別は全輪郭より 10 倍悪い。形態素処理か CNN で担保する |
| **train の小ささ** | 795 枚。シーン多様性が足りず過学習しうる。輪郭画素単位では 1,750 万あるが、画素は独立でない |

| **Lotus v1 との関係** | 本計画は Marigold V2 上で立てている。Lotus v1 でも同じ選別が効くかは別途測る価値がある（選別なしで +10.31% 出ていたので、上積みが見込める） |
