# 輪郭による深度の鋭化 — 操作は本物、輪郭の位置精度が足りない

実施: 2026-09-05 〜 09-06
評価: NYUv2, `processing_res=768`, Eigen crop, BF1 は Depth Pro 定義（t=5〜25 掃引）
前提: [`object_boundary_closure.md`](object_boundary_closure.md) / [`boundary_f1_findings.md`](boundary_f1_findings.md)

---

## 0. 結論

**輪郭を障壁として深度を埋め直す操作には、対照補正済みで +273% BF1 の上限がある。**
学習ゼロ、abs_rel も +1.4% 改善。これまで測ったどの経路より大きい。

**律速は輪郭の位置精度だけで、要求は 1.71px。**
YOLO-seg（2.24px）では正味 −6.6%、SAM（2.00px）で **+4.2%** と符号は反転するが、
上限の 1.5% しか回収できない。診断は正しかったが、
既存のセグメンテーションから十分な精度の輪郭が得られない。

---

## 1. 操作

真の深度不連続を**障壁**として扱う。輪郭の周り ±2px の帯を捨て、
**同じ側から**埋め直す。「同じ側」は帯を除いた連結性で決まるので、何も輪郭を跨がない。
**GT の深度値は使わない。** 輪郭が供給するのは位置だけ。

```
disc   = GT の不連続（深度比 > 1+t/100）
band   = dilate(disc, ±2px)
labels = 連結成分(valid & ~band) を帯へ幾何的に伝播
out[band] = 同じラベル内の局所平均（半径 3）
```

## 2. 埋め直しの窓半径が結論を支配していた

最初は半径 7 を根拠なく選び、掃引しなかった。**それが誤りだった。**

| 半径 | 完全な輪郭での BF1 | vs baseline |
|-----:|------------------:|------------:|
| 2 | 0.0457 | −3.0% |
| **3** | **0.2322** | **+393.2%** |
| 4 | 0.1222 | +159.6% |
| 5 | 0.0845 | +79.4% |
| 6 | 0.0775 | +64.6% |
| 7（当初） | 0.0458 | +19.5% |

半径 3 が鋭い最適値なのは偶然ではない。帯は不連続の両側 2px まで広がるので、
**半径 2 では帯の中心画素が自分側の帯外画素に届かず**何も起きない。
半径 3 でちょうど届き、**最も局所的な自分側の値**が入って段差が最も鋭く立つ。
半径 4 以上は遠くまで平均するので鈍る。
本来やりたいのは「最近傍の自分側の値」で、半径 3 がそれを最もよく近似している。

> **この誤りは、部分被覆で利得が負に振れたことから発見された。**
> 「線をトレースするだけならずれない、一部を消して測れ」という指摘がきっかけで、
> 半径 7 では印を付けなかった輪郭を跨いで平滑化していたことが分かった。
> **パラメータ 1 つが結論を反転させていた。**

### 撤回した結論

| 半径 7 での結論 | 半径 3 での正しい値 |
|----------------|-------------------|
| 完全な輪郭で正味 +81.4% | **+279.9%** |
| 1px ずれると崩壊 | 0.87px で +42.6%、1.71px で −2.7% |
| BF1 の大半は段差の大きさで決まり位置では取れない | **誤り**。位置だけで大半が取れる |

## 4. 何が効き、何が効かないか（300 枚、半径 3）

### 適合率 — 要求なし

| 追加した偽の輪郭 | BF1 | vs baseline |
|----------------:|----:|------------:|
| なし | 0.2721 | +314.3% |
| 真の輪郭の 1.0 倍 | 0.2721 | +314.3% |
| 真の輪郭の **2.0 倍** | 0.2716 | **+313.5%** |

**段差の無い場所に線を引いても無害。** 両側から自分側の値を取るだけなので、
平坦な場所では両側が同じ値になり何も変わらない。既存の段差を鋭くするだけで、
無い段差を作らない。

### 再現率 — ほぼ線形、どこでも正

| 保持率 | まとまり単位 | 散在的 |
|------:|------------:|-------:|
| 1.00 | +314.3% | +314.3% |
| 0.60 | +197.0% | +272.1% |
| 0.40 | +140.5% | +213.1% |
| 0.20 | +70.0% | +98.5% |
| 0.10 | +30.6% | +24.5% |
| 0.05 | **+12.5%** | +1.6% |

**5% しか拾えなくても正。** 付けた部分は直り、付けなかった部分はそのまま。

### 位置精度 — これが律速

| 実測ずれ中央値 | BF1 | vs baseline |
|--------------:|----:|------------:|
| 0.00px | 0.2721 | +314.3% |
| 0.87px | 0.0936 | +42.6% |
| 1.18px | 0.0703 | +7.1% |
| **1.71px** | 0.0639 | **−2.7%** |
| 2.65px | 0.0579 | −11.9% |

**1.7px を超えると利得が消える。** ずれた輪郭は偽陽性と偽陰性を同時に作るため。

## 5. 実際の YOLO マスクで（NYUv2 521 枚）

| 変種 | BF1 | vs baseline | abs_rel |
|------|----:|------------:|--------:|
| baseline | 0.0726 | — | 0.04913 |
| **yolo**（全輪郭） | 0.0671 | **−7.5%** | −0.1% |
| 移動対照 | 0.0718 | −1.0% | −0.0% |
| yolo_selected（Lotus 自身が段差を示す 42.9% のみ） | 0.0668 | −7.9% | −0.1% |
| perfect（GT の不連続） | **0.2707** | **+273.1%** | +1.4% |

**正味 −6.6%。上限の −2.4% しか回収していない。**

模擬では被覆率 7.9% から +20〜25% を見込んだが、実物では負になる。
模擬は各要素を独立に振っていたのに対し、**実物では位置ずれと被覆率が同時に効く**。
YOLO の実測 2.00px は既に許容（1.71px）を超えており、
被覆 7.9% の利得より、その 7.9% がずれていることの損失が上回る。

選択（Lotus の深度で絞る）も効かない（−7.9%）。適合率が問題ではないので当然。

## 6. 過去の記述の訂正

[`object_boundary_closure.md`](object_boundary_closure.md) は
「マスク輪郭が真の不連続から中央値 14.14px ずれている」を閉鎖理由とした。**これは不正確。**

14.14px は**段差が存在しない輪郭画素を含めた**値だった。
分解すると（`eval_contour_error_decomposition.py`, Hypersim 192 枚、合成の完全な GT）:

| | Hypersim | NYUv2 |
|---|--------:|------:|
| 段差が 8px 以内に無い輪郭画素 | **42.9%** | 64.1% |
| 段差がある場合の位置ずれ中央値 | **2.00px** | 2.83px |
| ↑ 2px 以内 | 54.3% | 41.2% |

**段差がある場所では、マスクは 2.00px で Lotus 自身（3.00px）より正確。**
NYUv2 で悪いのは GT が inpaint 済みで段差自体が消えているため。

結論は変わらないが、根拠は「14px ずれている」ではなく
**「2.00px ずれており、許容が 1.71px」**である。桁が違う。

Depth Pro との比較についても訂正する。0.409 は **Sintel**、我々は **NYUv2** で、
直接比較できない。桁の目安以上には使えない。

## 7. 輪郭の出どころを替える — SAM で符号は反転するが規模が足りない

足りないのは輪郭の位置精度だけ（要求 1.71px、YOLO は 2.00px）なので、
**物体検出はそのままに、マスク生成だけ差し替えて**測った。
YOLO の bbox をプロンプトとして SAM に渡し、同じ鋭化操作にかける。

### 位置精度（NYUv2 654 枚、段差が存在する画素に限定）

| | YOLO-seg | **SAM (ViT-H)** | 要求 |
|---|--------:|---------------:|-----:|
| 中央値 | 2.24px | **2.00px** | **< 1.71px** |
| 1px 以内 | 29.8% | 36.0% | — |
| 2px 以内 | 44.2% | 50.6% | — |
| 真の段差の 2px 以内を被覆 | 18.8% | **25.2%** | — |

### 鋭化の実測（NYUv2 521 枚、対照補正済み）

| 輪郭の出どころ | 鋭化後 BF1 | vs baseline | 対照 | **正味** | 上限の回収率 |
|---------------|----------:|------------:|-----:|--------:|------------:|
| YOLO-seg | 0.0671 | −7.5% | 0.0718 | **−0.0048（−6.6%）** | −2.4% |
| **SAM (ViT-H)** | 0.0748 | +3.1% | 0.0718 | **+0.0030（+4.2%）** | **+1.5%** |
| perfect（GT の不連続） | 0.2707 | +273.1% | — | — | 100% |

**符号が反転した。** 輪郭の質を上げるだけで −6.6% から +4.2% へ動く。
「位置精度が律速」という診断が正しかったことの直接的な裏付けである。

**しかし +4.2% は上限 +273% の 1.5% にすぎない。** abs_rel は −0.2% でほぼ変化なし。
手法として提示できる水準ではない。

### HQ-SAM は使えなかった

境界品質を明示的な目的とする [HQ-SAM](https://github.com/SysCV/sam-hq) が第一候補だったが、
transformers 5.12.1 の `SamHQModel` は 3 つの syscv-community チェックポイントすべてで
**箱プロンプトを無視したマスクを返す**（プロンプトした箱の内側に入るのはマスクの
16〜26%、素の SAM は同一画像で 100%）。
`intermediate_embeddings` を明示的に渡しても変わらない。移植側の問題と判断した。

素の SAM は HQ-SAM の土台なので、それが 2.00px に留まる以上、
HQ-SAM の上積みで 1.71px を切れたとは考えにくい。

### 残る余地は薄い

1. **必要な改善幅が大きい。** 2.00px → 1.71px は 15%。
   SAM は YOLO から 11%（2.24 → 2.00px）しか動かせなかった。
2. **より本質的に、この 2.00px は定義のずれを含む。**
   セグメンテーションは**意味的シルエット**を出し、必要なのは**深度不連続**の位置である。
   椅子の脚の間の背景、毛足の長い物体、透明物体では両者が一致しない。
   モデルを精密にしても消えない差である。

| 情報源 | 位置精度 | 正味 |
|--------|--------:|-----:|
| YOLO-seg | 2.24px | −6.6% |
| **SAM ViT-H** | **2.00px** | **+4.2%** |
| RGB Canny エッジ | 95% がテクスチャ | [不適](rgb_edge_route_closure.md) |
| Lotus 自身の不連続 | 3.00px | 不足（かつ循環） |
| 要求 | < 1.71px | — |
| GT | 0px | +273% |
