# 疎な深度点で大域誤差の何割が取れるか — 20 点で 43%

実施: 2026-09-01
ブランチ: `feature/object-depth-aux-loss`
前提: [`global_error_findings.md`](global_error_findings.md)

大域誤差（誤差の 55〜75%）には**後処理では届かない**ことを 3 経路の実測で確定させた
（[`global_error_findings.md`](global_error_findings.md) §4.5）。残るのは
「出力に無い情報を外から入れる」か「モデルを改善する」かで、
前者のうち最も現実的かつ測定可能な**疎な深度点**の効果を測った。

---

## 0. 要約

| 発見 | 数値 |
|------|------|
| **20 点で誤差の 43% が回復** | RBF 補間、学習不要 |
| 100 点で | **64.5%** |
| 500 点で | **76.6%**（低周波 Oracle の 75.3% に到達） |
| 全画素 Oracle（比較用） | tilt 22.6% / quad 36.1% |
| これまでの全手段の最良 | TTA **7.3%**、材質 5.3%、物体 2.1% |

**桁が違う。** そしてこれは反則ではない — LiDAR・SfM・ステレオが疎な深度点を返す設定は
実在し、それが depth completion というタスクそのもの。

---

## 1. 測定設計

`eval_sparse_points_ceiling.py` / 出力 `output/eval_sparse_points/` / Booster 228 フレーム

### 交絡の回避

標準プロトコルは**全 GT 画素で scale+shift を合わせている**。
そこを疎な点に置き換えると「疎な整合はノイジー」という別の要因が混入する。

そこで **標準の整合を済ませた予測を出発点**とし、
**疎な点は「残った誤差の補正」にのみ使う**。これで全画素 Oracle と直接比較できる。

### 補正の族（N 点のみから当てはめ）

| 族 | 形 | 対応する Oracle |
|----|-----|----------------|
| `tilt` | `a·x + b·y + c`（3 パラメータ） | 22.6% |
| `quad` | 完全 2 次（6 パラメータ） | 36.1% |
| `rbf` | thin-plate spline（滑らかな補間） | 低周波 75.3% |

各 N につきランダムな点集合を 5 回引いて平均。

---

## 2. 結果

| N 点 | tilt | quad | **RBF** |
|------|------|------|---------|
| 1 | −7.5% | −7.2% | −12.2% |
| 2 | −10.7% | −6.1% | −9.6% |
| 3 | −1844.6%※ | −29.7% | −3166.6%※ |
| 5 | 3.3% | −804.6%※ | 3.9% |
| 10 | 15.8% | −3.9% | **27.7%** |
| **20** | 20.2% | 27.8% | **43.0%** |
| 50 | 21.7% | 33.6% | 56.2% |
| 100 | 22.3% | 35.3% | **64.5%** |
| 500 | 22.6% | 35.9% | **76.6%** |
| （全画素） | 22.6% | 36.1% | — |

※ 点数がパラメータ数に対して少なすぎ、フィットが特異になる数値的アーティファクト
（ridge 項 1e-6 が小さすぎた）。実用上重要な **N≥10 の領域は安定**しており、
結論はそこにのみ依拠する。

### 読み取り

- **20 点で tilt Oracle（22.6%）の 90% に到達**（20.2%）
- **RBF は 20 点で quad Oracle（36.1%）を超える**（43.0%）— 多項式より柔軟なため
- **500 点で低周波 Oracle（75.3%）に到達**（76.6%）
- 点数と回復率は対数的に飽和する。**費用対効果の最良点は 20〜100 点**

---

## 3. これ自体が既に手法である

測定したのは「予測 + N 点 → 残差を点上で評価 → RBF 補間 → 減算」という
**学習不要の手続き**であって、Oracle ではない。実運用でも疎な GT は手に入るので、
**20 点で +43%、学習ゼロ**がそのまま成立する。

### 全手段の比較

| 攻めどころ | 到達可能な改善 | 種別 |
|-----------|---------------|------|
| 物体条件付け | 2.1% | 上限（実現せず） |
| 材質（対照補正後） | 5.3% | 上限（実現せず） |
| TTA（多解像度 / 反転） | 2.6〜7.3% | **実現済み** |
| **疎な点 20 個** | **43.0%** | **実現済み** |
| 疎な点 100 個 | 64.5% | 実現済み |

---

## 4. モデル側の改善（方針 A）の位置づけ

強いベースラインが手に入った状態でモデル側を測れる:

| | 手法 | 20 点での改善 |
|---|------|--------------|
| 対照 | RBF 補間（学習不要） | **+43.0%** |
| A | 疎な点を入力に取る凍結 UNet + zero-init 側枝 | ? |

RBF は**単に滑らかに補間する**だけだが、モデルなら**画像構造を見て補正の伝播範囲を
判断できる**（物体境界を越えて広げない、など）。これが学習の付加価値であり、
明確な比較対象がある状態で検証できる。

### 実装コストは低い

必要な部品は既にリポジトリにある:

| 部品 | 状態 |
|------|------|
| UNet 凍結 | `--use_lora` の `unet.requires_grad_(False)` |
| 入力チャンネル拡張の zero-init | `expand_unet_conv_in(..., zero_init=True)` |
| zero-init 出力層 | `ObjectAttentionEncoder` に前例 |
| checkpoint 保存・再開 | 実装済み・動作確認済み |

### 損失設計の訂正

当初「低周波成分に重み付けした損失」を提案したが、コードを読んで**誤りと判明**した:

- `anno_loss` は単純な MSE で、**誤差の 75% が低周波なら MSE は既にその 75% を見ている**
- `multiscale_gradient_loss`（重み 0.1）は**高周波を強調する**項で、提案と逆行する

**本当のズレは別にある**: 学習損失は alignment をしないが、評価指標は scale+shift を合わせる。
つまり**学習は「評価では消される成分」にも労力を使っている**。
これは原因 3（指標が測らない量を最適化していた）と同じ構図。

→ **scale-shift 不変な損失**にすべき（SILog / affine-invariant 損失。Marigold 等も採用）。

## 5. 留保

- Booster（12 Mpx, 鏡面・透明面主題）での測定。NYUv2 での確認は未実施
- 点はランダム一様サンプリング。実センサ（LiDAR の走査線など）の分布とは異なる
- N≤5 の数値は ridge 項が小さすぎて破綻している。再測定するなら ridge を上げること
- **先行研究の調査が必須** — Marigold-DC（拡散モデルによる zero-shot depth completion）が存在する
