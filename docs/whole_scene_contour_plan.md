# シーン全体の輪郭による鋭化 — 実装計画

作成: 2026-09-08
前提: [`contour_sharpening_findings.md`](contour_sharpening_findings.md) / [`contour_condition_results.md`](contour_condition_results.md)

---

## 0. なぜこの方向か

輪郭を障壁として深度を埋め直す操作には、**対照補正済みで +279.9% BF1** の上限がある
（学習ゼロ、abs_rel も +1.3% 改善）。本調査で唯一残っている本物の上限である。

その要求は 3 軸に分解済みで、**動かせる軸が 1 つに絞れている**。

| 軸 | 測定結果 | 現状 |
|----|---------|------|
| **適合率** | **要求なし**。真の輪郭の 2 倍の偽輪郭を足しても −0.8pt | 制約にならない |
| **再現率** | ほぼ線形、どこでも正。5% の被覆でも +12.5% | **SAM の物体マスクで 25.2%** |
| 位置精度 | **1.71px を超えると利得が消える** | SAM 2.00px（YOLO 2.24px） |

**適合率が無料である**ことが本計画の根拠である。過剰分割が罰されないので、
物体検出をやめて画像全体を分割してよい。段差の無い場所に線が増えても、
両側から自分側の値を取るだけなので何も変わらない。

そして被覆率こそが、物体検出を使う 7 方向すべてを閉じてきた原因だった。
可視化（`viz_contour_comparison.py`）でも、真の深度不連続の大半は
壁・床・柱・家具の内部構造にあり、COCO の 27 クラスの外にある。

### 副次的な仮説

2.00px という位置精度は**物体シルエットで測った値**である。
意味的境界と幾何的境界がずれる最悪のケース（椅子の脚の間の背景、毛足の長いもの、透明物体）が
そこに集中している。壁と床の境、柱の縁では両者が一致するため、
**全体に広げると位置精度も改善する可能性がある**。仮説なので測る。

## 1. 何を変えるか

```
現在:  YOLO の bbox → SAM（プロンプト付き）→ 物体マスク → 輪郭   1.66 個/画像
提案:  SAM automatic mode → シーン全体の領域分割 → 輪郭        73 個/画像
```

**物体検出を使わない。** SAM の automatic mask generation は点のグリッドを
プロンプトとして画像全体を領域に分割する。

### 実測済みのコスト（NYUv2 3 枚で計測）

| `points_per_crop` | 速度 | マスク数/画像 | 654 枚 |
|------------------:|-----:|------------:|-------:|
| 16 | 0.71 s/画像 | 50.3 | **8 分** |
| 32 | 1.47 s/画像 | 73.0 | **16 分** |

`transformers` の `pipeline("mask-generation")` で動く。
**fp16 は使えない**（NMS が `dets should have the same type as scores` で落ちる）。fp32 で回す。

### 実装後の実測（2026-09-08、NYUv2 3 枚）

`points_per_crop=32` で **73.0 領域/画像、輪郭が画素の 10.05%** を占める。
物体マスクの輪郭は約 1% だったので **10 倍**。**リスク 2 が現実の数字になった** ——
帯（輪郭 ±2px）はこの数倍に広がるため、埋め直しが局所平滑化に近づく懸念がある。
`points_per_crop` を 16 と 32 の 2 系列で生成し、面積比と利得の関係を見る。

生成の実測は 3.32 s/画像（654 枚で約 36 分）。3 枚計測時の 1.47 s より遅いのは、
初回のモデル読み込みが償却されない小標本だったため。

## 2. 実装

既存の測定装置がそのまま使える。**マスクの作り方だけが変わる。**

| 段階 | スクリプト | 変更 |
|------|-----------|------|
| マスク生成 | `build_sam_masks.py` | `--mode automatic` を追加（新規） |
| 被覆率・位置精度 | `eval_contour_error_decomposition.py` | `--mask_cache_dir` を差し替えるだけ |
| 鋭化の実測 | `eval_yolo_contour_sharpening.py` | 同上 |

保存形式は既存と同じ packed bits の `.npz`。`--union_only` 相当で
**全マスクの輪郭の和**を 1 枚に畳んで持つ（鋭化は和しか使わない）。

### 2.1 生成スクリプトの追加

`build_sam_masks.py` に `--mode {prompted,automatic}` を足す。

- `prompted`（既定・現状）: YOLO の bbox をプロンプトに使う
- `automatic`: `pipeline("mask-generation")` で全体を分割し、**各マスクの輪郭の和**を保存

自動モードは領域の**内部**ではなく**境界**が欲しいので、
マスクの和ではなく**輪郭の和**を取る点が prompted と異なる
（隣接領域の共有境界が、和を取ると消えてしまうため）。

**下流との整合**: 評価スクリプトは「マスクの和 → `contour_of` で輪郭抽出」を前提とする。
自動モードは既に輪郭を保存するので、そのまま流すと**輪郭の輪郭**（1 本の線が 2 本の
平行線になる）を取ってしまう。`--masks_are_contours` を
`eval_yolo_contour_sharpening.py` と `eval_contour_error_decomposition.py` に追加し、
明示的に分岐させた。

## 3. 判定基準（着手前に固定する）

比較対象は SAM の物体マスク（現状の最良）と、学習前の Lotus。

| ベースライン | 値 |
|-------------|----|
| 学習前 Lotus | BF1 **0.0693** / abs_rel **0.05000** |
| SAM 物体マスク | 被覆 **25.2%** / 位置 **2.00px** / 鋭化の正味 **+4.2%** |
| 完全な輪郭（上限） | +279.9% |

### 段階的なゲート

| # | 段階 | 条件 | 次へ進む判断 |
|---|------|------|-------------|
| **G1** | 被覆率 | 真の不連続の 2px 以内を覆う割合が **25.2% を明確に超える** | 超えなければ、全体に広げる意味がない |
| **G2** | 位置精度 | 段差がある場所での中央値が **2.00px 以下**を保つ | 悪化すれば、被覆の利得を食い潰す |
| **G3** | 鋭化の正味 | 移動対照を引いて **+4.2% を超える** | 超えなければ現状維持が最良 |
| **G4** | 実用 | BF1 が **0.0693 を超え**、abs_rel が悪化しない | ここまで通れば手法として提示できる |

**G1 と G2 は独立に測れる**（GPU 不要、数分）。G3 に進む前に両方確認する。

### 想定される 3 つの帰結

| 観測 | 解釈 |
|------|------|
| 被覆が上がり位置も保たれ、正味が伸びる | **副次仮説が正しい**。幾何的境界のほうが位置精度が良い |
| 被覆は上がるが位置が悪化し、正味が横ばい | 過剰分割が誤った線を増やしている。`pred_iou_thresh` で絞る余地 |
| 被覆がほとんど上がらない | SAM の自動分割も意味的領域しか出していない。方向を閉じる |

## 4. 既知のリスク

1. **自動分割は意味的領域を出す。** SAM は「物体らしさ」で分割するので、
   壁と床の境のような幾何的境界を出す保証はない。G1 がこれを直接測る。
2. **輪郭が増えすぎると帯が画像を覆う。** 73 マスク/画像の輪郭の和は、
   物体マスク（1.66 個）の数十倍になりうる。帯が広がりすぎると
   「埋め直し」が画像全体の平滑化に近づく。**帯の面積比を記録し、
   `points_per_crop` を 16 / 32 で振って影響を見る。**
3. **適合率が無料という測定は、偽輪郭が真の輪郭の 2 倍までで確認したもの。**
   自動分割はそれを大きく超える可能性があり、外挿になる。
   `eval_contour_coverage.py` の add 系列を 4.0 / 8.0 まで延長して確認する。
4. **NYUv2 の GT は inpaint 済み**で、位置精度の測定値が押し上げられる。
   Hypersim でも測って比較する（合成の完全な GT）。

## 5. 実装順序

1. ~~`build_sam_masks.py` に `--mode automatic` を追加、3 枚で煙試験~~ **完了**
   （`--mode` / `--points_per_crop` / `--pred_iou_thresh`、`contour_union()`、
   下流 2 本に `--masks_are_contours`）
2. **NYUv2 654 枚を生成**（`points_per_crop` 32 と 16 の 2 系列、計 約 60 分）
3. **G1 / G2 を測る** — `eval_contour_error_decomposition.py`、GPU 不要
4. G1・G2 が通れば **G3** — `eval_yolo_contour_sharpening.py`、移動対照込み
5. G3 が通れば **G4** と Hypersim hold-out での確認
6. リスク 3 の外挿を確認（`eval_contour_coverage.py` の add を 8.0 まで）

**G1・G2 までで約 30 分。** そこで方向の生死が決まる。
