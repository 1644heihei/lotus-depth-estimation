# テキスト条件付けの学習 — 結果

実施: 2026-09-04 〜 09-05
計画: [`text_conditioning_training_plan.md`](text_conditioning_training_plan.md)（判定基準は着手前に固定）
ブランチ: `feature/text-conditioning`

---

## 0. 結論

**5 つの判定基準のうち、意味のある形で通ったものはない。**

最も重要なのは (d) で、**cross-attention の lift がまったく動かなかった**（1.079 → 1.062〜1.070、微減）。
テキスト→領域の結合は 3000 step の学習後も 1.9% のままで、**機構が何も変化していない**。
したがって他の指標に現れた差はすべて副作用である。

そして (b) が決定的に失敗した。同じ LoRA 容量・同じ step 数で
**テキストなしに学習した対照（T-null）より、テキストを与えた run のほうが悪い**。
テキストは情報ではなくノイズとして働いた。

## 3. 判定（着手前に固定した基準に対して）

| # | 条件 | 結果 |
|---|------|------|
| a | `classes` > `shuffled`（同一 run 内） | **実質不成立**。差は +0.3〜0.6 ポイントで、**全 run で `generic` が `classes` を上回る**。学習前と同じ「内容は効かない」パターン |
| b | T-text / T-both の `classes` > T-null の `classes` | **失敗**。17.3% / 17.4% に対し T-null は **23.3%**。テキストを足すと対照より悪化 |
| c1 | abs_rel ≤ T-null/`empty` | 名目上通過（0.05766 vs 0.05783）だが差は 0.0002 で意味を持たない |
| c2 | abs_rel ≤ 0.05000（学習前） | **失敗**。全 run が学習前より悪い |
| d | lift が 1.079 から上昇 | **失敗**。1.062〜1.070 で微減 |

**(d) が通らない場合は他を信用しない**と事前に決めていた。ここでは他も通っていない。

## 4. 読み取れること

### 4.1 機構は動かなかった

lift が「動いて失敗した」のではなく**まったく動かなかった**。
3000 step の学習は、テキストを使わずに深度損失を下げる方向へ LoRA を動かした。
テキストは損失に対してほぼ無情報なので、それが最も安い解だったと解釈できる。

### 4.2 テキストは対照より悪い

(b) の失敗が本質的。同一条件でテキストなしの T-null が 23.3%、
テキストありの T-text が 17.3%。**テキストを与えたことが害になっている。**
プロンプトドロップアウト 0.1 で空プロンプト時の性能も保てていない
（T-null の empty 15.6% に対し T-text の empty 11.1%）。

### 4.3 空間バイアスは推論時に悪化させる

T-both の `classes` は ON で 0.06164 / 15.3%、OFF で 0.05730 / 17.4%。
lift 18.9 という強い介入をモデルが使えておらず、注意を歪めるだけになっている。
bias dropout 0.5 は「バイアスがあっても無視する」ことを学ばせた、という読みと整合する。

### 4.4 設計上の予測が外れた — fine-tune 税

計画 2.2 節で「`attn2` だけに絞れば深度経路を触らないので税は小さいはず」と書いたが、
**実測は −15.7%**（0.05000 → 0.05783）で、深度経路の LoRA
（[`adaptation_placement_findings.md`](adaptation_placement_findings.md): −4.6〜−12.6%）**より大きい**。

cross-attention は空プロンプト下でも学習された役割を持っており、
そこを動かすと壊れる、と解釈できる。「触る範囲を絞れば害が小さい」は成立しなかった。

### 4.5 学習後も内容非依存

学習前と同じく、全 run で固定文字列 `generic`（"an indoor scene"）が
正しいクラス名 `classes` を上回る。**学習しても内容が効くようにはならなかった。**

---

## 5. 区別できていないこと

lift が動かなかったのは「この方法では学習できない」からか、
「3000 step / rank 8 / LR 1e-5 では足りない」からか、**この測定では区別できない**。
計画の中断条件はこの場合に
「step 数か rank を上げるか、`text_encoder` の凍結解除を検討」としていた。

ただし (b) の失敗 —— テキストありが対照より悪い —— は、
規模を増やして向きが変わる種類の結果ではない。
テキストが有用なら、弱くても対照を上回る方向に出るはずである。

**Hypersim hold-out 評価は実施していない。**
計画では「NYUv2 で効かないのがドメインギャップのせいか」を分離するために置いたが、
(d) が示すとおり**機構が変化していない**ので、ドメインギャップが食う対象が存在しない。
必要なら 40 分で実施できる。

## 6. 物体検出という方針の総括

これで、物体検出が深度推定に足せる情報を測った経路は以下がすべて否定された。

| 経路 | 結果 | 出典 |
|------|------|------|
| 物体の深度**レベル** | 正味 −0.60%（対照以下） | [`object_oracle_control.md`](object_oracle_control.md) |
| 物体の**内部形状** | net/area が背景と同水準 | [`object_band_decomposition.md`](object_band_decomposition.md) |
| 物体の**周辺** | net/area が内部と同水準 | 同上 |
| 物体の**境界位置** | Lotus 自身が 4.7 倍正確 | [`object_boundary_closure.md`](object_boundary_closure.md) |
| RGB エッジによる位置補正 | 全設定で悪化 | [`rgb_edge_route_closure.md`](rgb_edge_route_closure.md) |
| **物体名（テキスト、学習なし）** | 内容非依存 | 本書 §2、`eval_text_prompt_conditioning.py` |
| **物体名（テキスト、学習あり）** | **対照より悪化、機構は不変** | **本書** |
