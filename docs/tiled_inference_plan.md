# タイル分割推論 実装計画

> [!WARNING]
> **本計画は実施済みで、手法は不採用となった。結果は
> [`tiled_inference_results.md`](tiled_inference_results.md) を参照。**
>
> 全設定でベースライン（0.05000）を下回った。決定的だったのは対照実験 C2 で、
> **latent 密度を全体パスと揃えても切り出しだけで −22.8%** 悪化した（654枚, 勝率 8.0%）。
> 視野を失うと単眼深度の手がかり（消失点・接地面・物体サイズ）が消えるため。
>
> さらに本計画 §1 の前提「モデルが得意な解像度を保ったまま latent 容量を増やせる」は
> 誤りだった。`processing_res` は**最大辺基準**なので、crop の latent 容量を増やすことは
> 拡大率を上げることと同一操作であり、分離できない。
> 366px の crop を 768 で処理すると 2.1 倍に拡大され、モデルが OOD になる。
>
> 以下は実施前の計画として記録のために残す。

## 1. 狙いと根拠

Phase 0 で以下が実測された:

| 根拠 | 数値 | 含意 |
|------|------|------|
| 解像度を上げると改善する | 512 → 768 で **+9.8%**（学習なし） | latent 容量がボトルネック |
| ただし上げすぎると悪化 | 1024 で **−14.4%** | モデルが OOD になる |
| 誤差は物体/背景で均等分布 | 誤差密度 0.89〜1.03 | 物体限定ではなく全面を攻めるべき |
| **誤差は境界/内部でも均等分布** | 内部（画素 86.6%）が**誤差の 78%** を保持 | **境界特化ではなく全面を攻めるべき** |
| **768 の利得も全面均等に出た** | 利得の **79.4% が内部領域**（画素比 86.6% とほぼ一致） | 解像度は境界を特別に直すのではなく全面を直す |

**素朴な解像度上げは 768 で頭打ちになる。それを超えるには、モデルが得意な解像度
（512〜768）を保ったまま、1 画素あたりの latent 容量を増やす必要がある。**
これがタイル分割推論であり、PatchFusion / BoostingMonocularDepth と同系統の考え方。

> [!IMPORTANT]
> **本計画の当初の想定は誤っていた（2026-08-27 訂正）。**
>
> 当初は「Lotus は VAE で 8 倍ダウンサンプルするため**境界がボケる** → 解像度を上げれば
> 境界が改善する」という機構を根拠にしていた。しかし
> [`phase0_findings.md`](phase0_findings.md) §3.5 の空間分解はこれを支持しない:
>
> - 境界上（±2px）の abs_rel は内部の **3.0 倍**（0.135 vs 0.044）で、境界が難しいのは事実
> - **しかし境界は全画素の 1.1%、誤差シェアはわずか 3.0%**（±20px まで広げても 21.9%）
> - **768 の利得の 79.4% は内部領域**で得られており、境界起因ではない
>
> **タイル分割が有望であるという結論は変わらないが、理由が変わる。**
> 「境界を鋭くする」のではなく「**内部領域を含む全面の latent 容量を増やす**」手法として
> 位置づけること。768 の利得が全面均等に出たことは、むしろ全面の latent 密度を上げる
> タイル分割が効くことを支持している。

**latent 密度の倍率** = 全体パスの原画像最大辺 ÷ タイルの原画像最大辺。
例: 640×480 を 2×2（重なりなし）に割ると 320×240 → 各タイルを processing_res=768 で
推論すると **latent 密度は 2 倍**（全体パスと同じ 96×72 latent が半分の領域を覆う）。

## 2. 手法設計

### 2.1 全体フロー

```
入力 RGB (640×480)
  ├─ 全体パス:  Lotus(res=768)                → D_global   構造は正しいが細部が粗い
  └─ タイルパス: 各タイル crop → Lotus(res=768) → D_tile_i  細部は細かいが scale/shift は任意
                      ↓
              アフィン整合 (D_tile_i → D_global)
                      ↓
              フェザー加重で融合
                      ↓
              D_fused (640×480) → 評価
```

Lotus の出力は**相対 disparity**（アフィン不定）。評価側でも最終的に
least-square alignment がかかるため、**融合結果の絶対スケールは問題にならない**。
重要なのはタイル間・全体との**相対的な整合性**のみ。

### 2.2 タイル幾何

| パラメータ | 記号 | 初期値 | 備考 |
|-----------|------|--------|------|
| グリッド | `G` | 2×2 | 3×3 も評価 |
| 重なり率 | `r` | 0.25 | 隣接タイルとの重複割合 |
| タイル推論解像度 | — | 768 | Phase 0 のピーク値を使う |
| 融合キャンバス | — | 原画像解像度 | GT が 640×480 のため。高解像度キャンバスは将来の改良案 |

タイル原寸: `tile_w = W / (G - (G-1)·r)`。2×2 / r=0.25 なら 640/1.75 ≈ 366 px
→ latent 密度は約 1.75 倍。

### 2.3 アフィン整合（タイルごと）

各タイル領域 `Ω_i` で、`a_i·D_tile_i + b_i ≈ D_global` となる `a_i, b_i` を最小二乗で求める。

- **disparity 空間**で fit する（評価側の alignment と同じ空間）
- **ロバスト化**: 残差上位 25% を除外して再 fit（既存 `fit_relative_disparity_calibration`
  と同じ考え方）
- **フェザー域を除外**して fit する（タイル端の劣化が係数を汚すのを防ぐ）
- `a_i <= 0` や非有限になった場合は shift のみにフォールバック

### 2.4 融合戦略（2 案を実装して比較）

**F1: フェザー加重平均（単純）**

```
w_i(x) = cosine ramp（タイル端で 0、内側で 1）
D_fused = Σ w_i · aligned(D_tile_i) / Σ w_i
```

- 実装が単純。ただしタイルが構造を誤ると、その誤りがそのまま出力に乗る。

**F2: 周波数分離（ディテール転写）— 本命**

```
D_fused = lowpass(D_global) + Σ w_i · [ aligned(D_tile_i) - lowpass(aligned(D_tile_i)) ] / Σ w_i
```

- **低周波（大域構造）は全体パスから、高周波（細部）だけタイルから**取る
- タイルが大域構造を誤っても出力が破綻しない（BoostingMonocularDepth と同じ発想）
- lowpass はガウシアン。カーネル幅 `σ` はアブレーション対象（latent セル相当が目安）

初期実装は **F2 を本命、F1 を対照**として両方持つ。

## 3. 実装構成

### 3.1 新規ファイル

| パス | 役割 |
|------|------|
| `utils/tiled_depth_fusion.py` | タイル幾何生成 / アフィン整合 / フェザー重み / F1・F2 融合 |
| `eval_tiled_depth_nyuv2.py` | 評価ドライバ（アブレーションフラグ付き） |
| `train_scripts/run_tiled_ablation.ps1` | アブレーション一括実行（レジューム付き） |
| `docs/tiled_inference_results.md` | 結果記録（実施後） |

既存ファイルは**変更しない**（`eval_regressor_predepth_nyuv2.py` 等はそのまま）。

### 3.2 `utils/tiled_depth_fusion.py` の主要 API

```python
def make_tiles(h, w, grid=2, overlap=0.25) -> list[Tile]
    """Tile(x1,y1,x2,y2) のリストを返す。端は画像内に収める。"""

def feather_weight(tile, h, w, ramp_px) -> np.ndarray   # [H,W] float32, 端で0
def fit_affine(src, dst, mask, trim=0.25) -> tuple[float,float]  # ロバスト最小二乗
def fuse_average(global_disp, aligned_tiles, weights) -> np.ndarray          # F1
def fuse_detail_transfer(global_disp, aligned_tiles, weights, sigma) -> ...  # F2
```

### 3.3 予測キャッシュ

Phase 0 の `eval_object_oracle_ceiling.py` と同じ方式を踏襲する:

- 全体パス・各タイルの生 disparity を `.npy`(float16) でキャッシュ
- 融合パラメータ（F1/F2, σ, 重み）のアブレーションは**再推論なしで回せる**
- キャッシュ先: `D:/lotus/data/tiled_cache/{grid}x{grid}_r{overlap}/`

これにより、アブレーション 1 本あたりの実行時間が数分 → **数十秒**になる。

### 3.4 実装上の注意

- fp16 パイプラインには `torch.autocast(device_type=...)` が必須
  （Phase 0 で踏んだ罠。詳細は [`phase0_findings.md`](phase0_findings.md) §2.1）
- `match_input_res=True` にすると**タイルの原寸**で返る。融合はこの原寸で行う
- NYUv2 評価は eigen crop `[45:471, 41:601]` のみを採点するが、
  **タイルは画像全体を覆う**こと（crop 外もタイルの文脈として必要）
- `resize_max_res` は最大辺基準。タイルのアスペクト比が原画像と異なる点に注意

## 4. 検証計画

### 4.1 比較基準

**新ベースラインは `processing_res=768` の abs_rel 0.05000。**
512 の 0.05543 と比べると実力より 9.8% 良く見えるため、必ず 768 と比較する。

### 4.2 対照実験（v6 の教訓 — 最初から同時に回す）

タイル分割の利得が「解像度」由来なのか「切り出し・アンサンブル」由来なのかを切り分ける。
**これを欠くと Phase 1〜2 と同じ解釈ミスを繰り返す。**

| 対照 | 内容 | 何を切り分けるか |
|------|------|------------------|
| **C1 アンサンブル対照** | 全体パスを N 回（seed 違い）実行して平均 | 利得は単なる平均化の効果ではないか |
| **C2 同 latent 密度対照** | タイルを切るが、latent 密度が全体パスと**等しくなる** processing_res で推論 | 利得は解像度由来か、切り出し由来か |
| **C3 全体パスのみ** | res=768（= 0.05000） | 基準 |

**C2 が本質的**: もし C2 が本番と同等の利得を出すなら、効いているのは解像度ではなく
「狭い視野で推論すること」であり、手法の説明が変わる。

### 4.3 アブレーション

| 軸 | 値 |
|----|-----|
| グリッド | 2×2 / 3×3 |
| 重なり率 | 0.15 / 0.25 / 0.35 |
| 融合 | F1（平均） / F2（周波数分離） |
| F2 の σ | latent セル相当 ×{0.5, 1, 2} |
| アフィン整合 | ロバスト trim あり / なし |

キャッシュがあるため、推論は「グリッド × 重なり率」の 6 通りのみ。
残りは融合パラメータなので再推論不要。

### 4.4 指標

- `abs_rel` / `δ1`（主指標、NYUv2 654枚、既存プロトコル）
- `roi_abs_rel` / `bg_abs_rel`（どの領域が改善したか）
- **境界領域の誤差**（深度不連続 ±k px）— 細部が実際に改善したかの直接確認
- タイル継ぎ目のアーティファクト有無（可視化で目視確認）

## 5. 判定基準（kill criteria）

| 条件 | 判断 |
|------|------|
| 2×2 + F2 が **0.05000 を下回らない** | 融合実装のバグを疑う → 継ぎ目・整合を可視化して検証 |
| 全設定を試して **改善 < 3%** | 複雑さに見合わない。解像度の発見（+9.8%）を主成果として報告し、タイルは付録扱い |
| **C2 が本番と同等** | 「解像度が効く」という説明が誤り。手法の位置づけを再定義 |
| 改善 ≥ 5% かつ継ぎ目なし | 成功。物体検出ガイド（§6）へ進む |

## 6. 物体検出の組み込み（Stage 2 — §5 で成功した場合のみ）

判定 3（物体は誤差の集中点ではない）より、
**物体検出を「タイルを置く場所の決定」に使う**のが妥当な役割。

| 案 | 内容 | 期待 |
|----|------|------|
| **D1 適応タイル配置** | 均等グリッドに加え、検出物体を中心とするタイルを追加 | 物体の細部を選択的に高密度化 |
| **D2 境界を跨がない融合** | seg マスク境界でフェザー重みを切り、物体と背景を混ぜない | 境界のにじみを抑制 |
| **D3 タイル優先度** | 物体を含むタイルの重みを上げる | 効果は限定的と予想（判定 3 より） |

**必ず「均等タイルのみ」を対照として同時に回すこと。**
判定 3 より物体領域は面積相応の誤差しか持たないため、
D1〜D3 の利得は小さいと予想される。**ここで有意差が出なければ、
物体検出は本手法に寄与しないと結論づけて構わない**（それも一つの成果）。

なお D2（境界を跨がない融合）は、seg マスクを**空間的に**使う初めての実装になる
（現行は矩形のみで、マスクは破棄されている）。マスクのキャッシュは
Phase 0 で作成済み（`D:/lotus/data/oracle_cache/yolo_seg/`）なので再利用できる。

## 7. 想定される限界

### 7.1 NYUv2 は 640×480 と低解像度

`processing_res=768` は既に原画像を拡大しており、タイル分割で得られるのは
**latent 容量の増加**であって、原画像にない情報は生まれない。
原画像の情報量が上限を規定するため、**NYUv2 での利得は数%に留まる可能性が高い**。

対策: 高解像度データセット（DIODE / Middlebury / 高解像度 ScanNet）での追試を
Stage 3 として計画する。手法の実力を示すにはそちらが適切。

### 7.2 タイルの視野欠落

タイルは文脈（部屋全体の構造）を失うため、単体では深度構造を誤りやすい。
F2（周波数分離）はこのリスクを構造的に回避する設計だが、
タイルを小さくしすぎる（3×3 以上）と高周波成分自体が信用できなくなる可能性がある。

### 7.3 計算コスト

1 画像あたり 全体 1 + タイル `G²` パス。2×2 なら 5 パス、3×3 なら 10 パス。
654 枚 × 5 パス ≈ 15 分程度（res=768, fp16）。実験としては許容範囲。

## 9. この計画が Phase 0 の教訓をどう反映しているか

| Phase 0 の教訓 | 本計画での反映 |
|----------------|----------------|
| 手法を作る前に上限を測る | T1 の最小構成を先に通し、利得の有無を早期に判定（T4 の作り込み前） |
| ベースラインを同一プロトコルで持つ | 全比較を res=768 / 0.05000 に対して行う（§4.1） |
| 対照実験を最初から回す | C1〜C3 を T3 で必ず実施。D1〜D3 も均等タイル対照付き（§4.2 / §6） |
| 単純な設定を先に試す | F1（単純平均）を F2 の前に通す |
| kill criteria を事前に決める | §5 に明文化。改善 < 3% なら撤退 |
