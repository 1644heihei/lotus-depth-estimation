# 輪郭条件付き Lotus の本学習 — 論文級 実装計画

作成: 2026-09-19
前提: [`whole_scene_contour_results.md`](whole_scene_contour_results.md) /
[`contour_condition_results.md`](contour_condition_results.md)

---

## 0. 枠組みが変わる

これまでの学習はすべて**公開 Lotus に LoRA を足す追加学習**だった。
比較対象が公開チェックポイントなので、**学習しただけで BF1 が −32% 落ちる**（「税」）を
先に埋める必要があり、条件付けの効果を見る前に不利を背負っていた。

**本計画は Stable Diffusion 2 から Lotus 自体を学習し直す。**
比較対象は公開モデルではなく、**同一予算で学習した輪郭なしの自分のモデル**になる。

| | LoRA 追加学習（従来） | **本学習（本計画）** |
|---|---|---|
| 起点 | `jingheya/lotus-depth-d-v2-0-disparity` | `stabilityai/stable-diffusion-2-base` |
| 学習する重み | 1.66M（全体の 0.19%） | **867.6M（全体）** |
| 比較対象 | 公開 Lotus | **自分で学習した条件なしモデル** |
| 「税」 | −32%、越えるべき壁 | **概念として消える** |
| 主張の形 | 「公開モデルを改善した」 | **「同条件 ablation で輪郭が効く」** |

**税が消えるのが本質的な違いである。** 条件なしモデルも同じ予算・同じ劣化を負うので、
差分がそのまま輪郭の寄与になる。

---

## 1. 何を条件として与えるか

**SAM automatic mode による画像全体の分割輪郭。** 物体検出は使わない。

理由は測定で確定している（[`whole_scene_contour_results.md`](whole_scene_contour_results.md)）。

| 輪郭 | 真の段差の被覆 | 後処理での正味 |
|------|-------------:|-------------:|
| YOLO 物体マスク | 18.8% | −6.6% |
| SAM 物体マスク | 25.2% | +4.2% |
| **SAM 全体分割（grid 32）** | **75.3%** | **+18.4%** |

前回の学習（[`contour_condition_results.md`](contour_condition_results.md)）が使ったのは
**物体マスク**で、後処理でも +4.2% しか出ない輪郭だった。本計画はその 4 倍の情報を与える。

## 2. 実測した数値

計画の見積もりはすべて本環境の実測に基づく。

| 項目 | 実測値 |
|------|--------|
| GPU | RTX 4090 / VRAM **25.8 GB** |
| **全 UNet 学習の速度** | **2.09 s/step**（bsz 8, res 512, bf16, gradient checkpointing） |

| ディスク空き | 490 GB |

## 3. 予算

### 学習

| 設定 | 1 run | 3 run |
|------|------:|------:|
| 20,000 step（既存 `train_lotus_d_core.ps1` と同じ） | **11.6 h** | **34.8 h** |
| 30,000 step | 17.4 h | 52.2 h |

### 輪郭の生成（最長工程）

20,000 step × bsz 8 = **160,000 サンプル**。Hypersim 全体は 59,543 枚なので 2.7 エポック。

| 生成する枚数 | 生成時間 | エポック数 |
|------------:|--------:|----------:|
| 15,000 | 18.8 h | 10.7 |
| **25,000** | **31.2 h** | **6.4** |
| 59,543（全体） | **74.4 h** | 2.7 |

**25,000 枚を推奨。** 全体生成の 74 時間は投資として大きすぎ、
10 エポック超は過学習の恐れがある。6.4 エポックは中庸。

**シーンをまたいで散らして選ぶ**こと（hold-out 分割と同じ方式）。
連続フレームを取ると同じ部屋ばかりになる。

### 合計

| 工程 | 時間 |
|------|-----:|
| 輪郭生成（25,000 枚） | 31 h |
| 学習 3 run × 20,000 step | 35 h |
| 評価 | 3 h |
| **合計** | **約 70 h（3 日弱、生成と学習は逐次）** |

## 4. 学習する 3 本

| run | 輪郭チャンネル | 目的 |
|-----|--------------|------|
| **P-null** | 常に空（−1） | **本計画の基準**。輪郭なしで同一予算で学習した Lotus |
| **P-cont** | その画像の全体分割輪郭 | 本命 |
| **P-shuf** | 他画像の輪郭 | 中身が効いているのか、チャンネルが埋まっていれば良いのかの分離 |

共通設定（`train_lotus_d_core.ps1` に準拠）:
SD2-base 起点 / **全 UNet 学習（`--use_lora` なし）** / LR 3e-5 constant / warmup 0 /
batch 8 / res 512 / 20,000 step / bf16 / `norm_type=trunc_disparity` / seed 42 /
Hypersim hold-out 20 シーン除外。

`conv_in` は 4ch → 8ch に拡張（`expand_unet_conv_in(zero_init=True)`）。
**全体学習なので凍結の問題は起きない**が、
[前回の事故](contour_condition_results.md#6-実装の失敗とその教訓)を踏まえ
`extra_channel_energy() > 0` の検査は残す。

## 5. 評価

### 本命（論文の表になる）

| データセット | 状態 | 備考 |
|------------|------|------|
| **NYUv2** | **手元にある**（654 枚） | 本調査の基準。BF1 / abs_rel / δ1 |
| **Hypersim hold-out** | **手元にある**（20 シーン 300 枚） | in-domain、完全な GT |
| **Booster** | **手元にある**（228 枚） | 実測ステレオ GT、12Mpx、境界が鋭い |
| ScanNet | 手元にある（104MB tar） | 分割定義あり |
| KITTI / ETH3D / DIODE | **分割定義のみ、実データ無し** | **要ダウンロード** |

**KITTI・ETH3D・DIODE が欠けている。** Marigold / Lotus の標準プロトコルは
NYUv2・KITTI・ETH3D・ScanNet・DIODE の 5 点セットなので、
論文級を名乗るなら取得が要る。容量は数十 GB 規模。**着手前に確認すること。**

### 指標

| 指標 | 何を見るか |
|------|----------|
| **BF1**（Depth Pro 定義） | **主要評価項目**。輪郭が直すべきもの |
| abs_rel / δ1 | 境界の改善を精度の犠牲で買っていないか |
| recall ON / OFF edge | 「画像に見えない段差」を拾えるようになったか |

## 6. 判定基準（着手前に固定する）

主要評価項目は **BF1**、データセットは **NYUv2**。

| # | 条件 | 排除するもの |
|---|------|-------------|
| **a** | P-cont > **P-shuf** | チャンネルが埋まっているだけの摂動 |
| **b** | P-cont > **P-null** | チャンネル追加そのものの効果 |
| **c** | abs_rel が P-null 以下 | 境界を精度で買っていない |
| **d** | a・b が **Hypersim hold-out と Booster でも**成立 | NYUv2 固有でない |

**a と b の両方が要る。** a だけでは「輪郭らしい入力なら何でも効く」を否定できず、
b だけでは「この画像の輪郭であること」を分離できない。

### 補助的に見るもの（判定には使わない）

- P-cont を**空チャンネルで評価**した値 —— 輪郭なしでも動くか
- P-null に**後処理の鋭化**を掛けた値 —— 学習と後処理のどちらが強いか
  （後処理は同じ輪郭で +18.4% 出る。**学習がこれを下回るなら、学習する意味がない**）

**最後の比較が本計画の実質的な合否である。**

## 7. リスク

1. **SD2-base が取得できない。** 本環境では
   `stabilityai/stable-diffusion-2-base is not a valid model identifier` で失敗した
   （認証かネットワーク制限）。**最初に解決すること。** 解決しなければ本計画は成立しない。
2. **単一 GPU で公開 Lotus の品質に届かない可能性。** 原論文の設定・データ量・
   ハイパーパラメータを完全再現できる保証はない。ただし **ablation としては成立する**
   —— 比較対象が自分の P-null だから。この点は論文中で明示すること。
3. **6.4 エポックは過学習しうる。** 20,000 step / 25,000 枚。
   validation を 500 step ごとに取り、劣化点を記録する。
4. **KITTI / ETH3D / DIODE の欠如。** 屋外データが無いと汎化の主張が弱い。
   VKITTI も未取得（`TRAIN_DATA_DIR_VKITTI=""`）なので、**屋内特化**として
   位置づけるか、データを揃えるかの判断が要る。
5. **後処理に負ける可能性。** 同じ輪郭で後処理は +18.4% 出る。
   学習がそれを下回れば、「学習を伴う手法」という要件は満たしても、
   **性能では後処理に劣る**という結論になる。これは事前に受け入れるべきリスクである。

---

## 8. 実装順序

1. **SD2-base の取得を解決**（リスク 1）。これが通らなければ以降は無意味
2. KITTI / ETH3D / DIODE を取得するか、屋内特化に絞るかを**決める**
3. Hypersim から 25,000 枚をシーン横断で選定（hold-out 20 シーンは除外）
4. **輪郭を生成**（31 h、最長工程なので先に着手）
5. `train_lotus_d.py` の `--contour_condition` を全体学習で煙試験（500 step、
   `extra_channel_energy() > 0` と輪郭が実際に流れることを確認）
6. **P-null** を先に回す（基準が先にあれば以降の判定が即座にできる）
7. **P-cont** → **P-shuf**
8. 評価と判定。**後処理との比較を忘れないこと**

## 9. 縮小版という選択肢

**20,000 step が重すぎる場合、5,000 step × 3 本（8.7 h）でも ablation は成立する。**
主張は「計算資源の制約下で、同条件比較により輪郭情報の効果を示した」になる。
絶対性能は公開 Lotus に劣るが、**a・b・c・d の判定は同じように下せる**。

輪郭も 10,000 枚（12.5 h 生成、4 エポック）で足りる。**合計 24 h、1 日**。

まず縮小版で判定を出し、**効果が確認できてから論文級に投資する**のが合理的である。
効かなければ 70 時間を節約できる。
