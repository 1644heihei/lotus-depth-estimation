# 境界F1で測り直したら、物体境界の上限は +313% だった

> **続報**: この上限は本物だが、YOLO-seg では到達できない。
> マスク輪郭は真の深度不連続から中央値 14px ずれており、Lotus 自身の輪郭のほうが 4.7 倍正確だった。
> 方針の閉鎖と根拠は [`object_boundary_closure.md`](object_boundary_closure.md) を参照。
> 本書の第 6 節「次に測ること」はそこで実施済み。

実施: 2026-09-03
スクリプト: `eval_boundary_f1.py`
評価: NYUv2 test のうち物体が検出された 522 枚, `processing_res=768`, Eigen crop
対照: 同形状の帯を円環シフト、3 回平均

前提: [`object_band_decomposition.md`](object_band_decomposition.md)

---

## 0. 前回の判定を訂正する

帯分解で物体境界 Oracle を **abs_rel +0.8〜2.6%** と測り、
「既存手法の実測値の 1/10 で勝負にならない」として候補を閉じた。**この判定は誤りだった。**

原因は 2 つ。

### 誤り 1: 物差しが不適切だった

abs_rel は画素平均である。±2px の帯は全画素の 1.7% しか占めないので、
**すべての画素を等しく重み付ける指標では境界手法の効果が構造的に埋もれる**。
この分野が境界の評価に F1 を使うのは、まさにそのためである。
境界手法を abs_rel で評価するのは、指標の選択自体が結論を決めていた。

### 誤り 2: 事実関係を取り違えていた

SharpDepth の記述から「この分野では Marigold / Lotus は境界が鋭い側に分類されている」と書いたが、
定量ベンチマークは逆だった。Depth Pro (arXiv 2410.02073) の Sintel 境界 F1:

| モデル | 境界F1 |
|--------|-------:|
| Depth Pro | 0.409 |
| Depth Anything V2 | 0.228 |
| MiDaS | 0.181 |
| **Marigold** | **0.068** |

潜在拡散系が最下位で、Depth Pro の 6 分の 1。Lotus は Marigold と同じ VAE を使う。

## 1. 指標

Depth Pro の定義に従う。遮蔽輪郭は隣接画素の**深度比**から取る。

    c_d(i,j) = [ d(j)/d(i) > 1 + t/100 ]

比なのでスケール不変であり、相対深度の予測にそのまま適用できる。
閾値は t = 5 から 25 まで 11 点掃引し、高い t に重みを置いて平均。
F1 は P と R について対称なので、precision / recall の割り当ての流儀は結果に影響しない。

隣接は上下左右 4 方向。両画素に GT がある対のみ数える。
`np.roll` の巻き込み分は端の行・列を無効化して除去。

**健全性確認**: 全画素を GT に置換した `oracle_all` は全閾値で F1 = 1.0000 になる。

## 2. 結果

| 変種 | BF1 | vs baseline | abs_rel | vs baseline |
|------|----:|------------:|--------:|------------:|
| baseline (Lotus) | **0.0728** | — | 0.04938 | — |
| **oracle_band**（輪郭 ±8px に GT） | **0.3423** | **+370.2%** | 0.04554 | +7.8% |
| ↑ の移動対照 | 0.1142 | +56.9% | 0.04630 | +6.2% |
| oracle_mask（シルエット全体に GT） | 0.3441 | +372.7% | 0.04110 | +16.8% |
| oracle_all（健全性確認） | 1.0000 | — | 0.00000 | — |

**対照を引いた正味: BF1 +0.2280（baseline 比 +313.3%）、abs_rel は +1.54 ポイント。**

## 3. 読み取れること

### 3.1 同じ Oracle が物差しで 200 倍違って見える

| 物差し | 正味 | 解釈 |
|--------|-----:|------|
| abs_rel | +1.54 ポイント | 追う価値なし |
| BF1 | +313.3% | 4.7 倍の改善 |

指標の選択だけで結論が反転する。これは本研究で繰り返し使ってきた
「Oracle 上限 + 一致対照」という手続きに、**指標の妥当性という第 3 の軸**が要ることを示している。

### 3.2 Lotus のベースラインは Marigold と同水準

BF1 = 0.0728 は、Depth Pro が Sintel で報告する Marigold の 0.068 とほぼ一致する。
データセットが違うのに同水準なのは、**両者が共有する VAE に起因する欠陥**である傍証。
Lotus も同じ弱点を継いでいる。

### 3.3 薄い帯だけで足りる

`oracle_band` 0.3423 と `oracle_mask` 0.3441 はほぼ同じ。
**画素の 6.6% しかない帯が、シルエット全体を渡した場合の 99.5% を回収する。**
一方 abs_rel では帯はシルエット全体の 46%（7.8 / 16.8）しか取れておらず、
**2 つの指標が帯とマスクに逆の順位を付ける**。

### 3.4 位置が効いている

同面積の帯を無関係な場所へ移すと 0.1142 までしか上がらない（正味 0.2280 が残る）。
これまで物体条件付けの検証は正味ゼロが続いていた
（[`object_oracle_control.md`](object_oracle_control.md): Oracle A bbox 正味 −0.60%）。
**物体検出が対照を明確に超えたのは、この測定が初めて。**

## 4. 残る留保

1. **NYUv2 の GT は inpaint 済み**で、GT 自身の遮蔽輪郭が鈍っている。
   Depth Pro がこの指標を合成データ（Sintel, Spring）とマッティングデータで測るのはそのため。
   絶対値は参考値、**baseline と Oracle の差**が知見。
   Booster（実測ステレオ GT, 12Mpx）での再測が望ましい。
2. **Oracle は構成上 GT の輪郭を埋め込む**ので BF1 が上がるのは当然、という批判はあり得る。
   対照（移動帯 0.1142）がその批判に答えている：GT を同数の画素に配っても、
   場所が違えば 0.1142 止まり。
3. **実手法が上限のどれだけを取れるかは未測定。** これが次の検証。

---

## 5. 先行研究との関係

- [PointDiT (2026)](https://arxiv.org/pdf/2607.02515) は同じ問題を
  「VAE を捨ててピクセル空間拡散にする」ことで解き、BF1 最高（9.41 → 10.50）。
  Lotus の速度上の利点（Marigold の数百倍速）を捨てる解法。
  **潜在空間を保ったまま境界を直せるなら、そこに立つ余地がある。**
- 境界精緻化の系譜（[SharpNet 2019](https://arxiv.org/pdf/1905.08598),
  [Instance Convolutions 2021](https://arxiv.org/pdf/2112.01521),
  [SDDR 2024](https://arxiv.org/pdf/2409.17880)）はいずれも CNN 時代の識別モデル向けで、
  **潜在拡散世代での再検証は調査した範囲で見つからなかった。**

## 6. 次に測ること

学習を伴わない後処理で、この上限のどれだけを取れるか。
条件付けの学習は必ず fine-tune 税を払う
（[`adaptation_placement_findings.md`](adaptation_placement_findings.md): 同一パラメータ数で −4.6〜−12.6%）。

候補: YOLO-seg の輪郭を跨ぐ平滑化を抑えるガイド付きフィルタ / joint bilateral /
輪郭に沿った深度の再量子化。いずれも学習ゼロで試せる。

**abs_rel を劣化させずに BF1 を上げられるか**が判定条件。
