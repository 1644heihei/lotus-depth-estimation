## 0. 結論

**手法は転移しなかった。しかし問題は残っている。**

| | Lotus v1 | Marigold V2 |
|---|---:|---:|
| baseline BF1 | 0.069336 | **0.088351** |
| 鋭化後（生） | 0.076486 (**+10.31%**) | 0.086675 (**−1.90%**) |
| 移設対照 | 0.063760 (−8.04%) | 0.082854 (−6.22%) |
| **正味** | **+18.35%** | **+4.32%** |
| **オラクル上限** | +279.9% | **+209.8%** |
| 上限の回収率 | 6.6% | 2.1% |

2 つの事実が同時に成り立つ。

1. **生の増分が符号反転した**（+10.31% → −1.90%）。Marigold V2 では鋭化が
   正しい情報を壊す量が直す量を上回る。正味 +4.3% が正に見えるのは、
   移設対照がもっと壊れているからにすぎない。
2. **オラクル上限は +209.8% のまま。** GT 輪郭を使えば BF1 は 3 倍になる。
   **土台の進化は境界問題を解いていない。**

abs_rel は 0.03881 → 0.03898（−0.4%）でほぼ不変。精度を売って境界を買ったのではない。

### 事前に固定した判定との対応

| 基準 | 実測 | 該当 |
|---|---|---|
| BF1 ≥ 0.12 かつ 正味 ≤ +3% → 畳む | BF1 0.0884、正味 +4.3% | どちらも不成立 |
| 正味 ≥ +10% → SOTA 改善と書ける | band 5 で +10.47% | **形式上は該当、実質は不成立**（§3.3） |
| 正味 +3〜10% → 弱まったが生存 | +4.3%（v1 と同設定） | 該当 |
| オラクル上限 ≥ +150% → 余地は構造的 | +209.8% | **該当** |

判定基準そのものに抜け穴があった。**「正味」は生が正のときしか改善を追わない。**
Marigold V2 では生が全設定で負なので、正味の大小は対照の壊れ方を測っているにすぎない。
詳細は §3.3。今後この種の判定を書くときは**「生がベースラインを上回ること」を
必須条件として明記する**。

## 2. 検証したこと

負の結果を報告する前に、器具が正しいことを 3 点で確認した。

### 2.1 aligner の正しさ

`align_to_gt` は視差前提（`pred_disp > 0` で絞る）だが、`Log-stage2` は
アフィン不変 **log depth** を [−1, 1] で出す。log 空間版を新設した
（[`utils/align_space.py`](../utils/align_space.py)）。

| aligner | abs_rel | δ1 |
|---|---:|---:|
| **log**（正） | **0.03881** | **0.9797** |
| disparity（誤用） | 0.10824 | 0.8695 |

**δ1 0.9797 が論文の 98.0% とほぼ一致**することが決定的な裏づけである。

論文の AbsRel 3.6% との差 0.28pt は GT の選び方で説明できる。NYUv2 labeled には
`depth_`（生）と `filled_`（補間済み）があり、`list_nyu_pairs` は `depth_` を使う。
既存結果すべてが `depth_` で測られているので、比較の一貫性を優先して `depth_` を維持した。

### 2.2 採点の一貫性

同じ実行の中で Lotus v1 も測り直し、**BF1 が記録値 0.069336 と完全一致**した。
aligner の追加は既存の採点経路を変えていない（既定は `disparity` のまま）。

### 2.3 母集団

654 枚。`eval_yolo_contour_sharpening.py:149` は `if not pp.is_file(): continue` で
**欠損を黙って飛ばす**ので、実行前に 654 個のキャッシュパス存在を assert した。
過去に 521 枚と 654 枚を混ぜて baseline が 0.0726 と 0.0693 に割れた事故の再発防止。

## 3. 掃引 — パラメータ未調整の産物ではない

`fill_radius=3` / `band_px=2` は Lotus v1 の鈍さに合わせた値なので掃引した。

### 3.1 掃引で見つかった制約 — `radius > band`

`refill_from_own_side` の参照元は `src = (labels == lab) & ~band`、すなわち**帯の外側**である。
帯の中心にある画素から最も近い帯外画素までは `band+1` あるので、
ぼかし窓 `(2*radius+1)` が届くには **`radius > band` が必要**。

満たさない設定は `den ≈ 0` となり埋め直しが起きず、**警告もエラーもなく no-op になる**。
最初の掃引 7 通りのうち **4 通りがこれだった**。オラクル上限が 0% 付近
（−1.5% 〜 −0.1%）になることでしか気づけない。

この制約は既存 doc に書かれていなかった。Lotus v1 の「radius 3 が最良、7 は +19.5%」も、
**band 2 における最小の有効値が 3 だった**という意味であり、掃引すべき軸は
`radius` ではなく `band`（`radius = band+1` に固定）だったことになる。

### 3.2 有効な設定の全結果

| band | radius | 生 | 対照 | 正味 | 上限 |
|---:|---:|---:|---:|---:|---:|
| 1 | 2 | −2.04% | −3.23% | +1.18% | 179.4% |
| 1 | 3 | −10.12% | −4.47% | −5.65% | 67.8% |
| 2 | 3 | −1.90% | −6.22% | +4.32% | **209.8%** |
| 3 | 4 | −2.08% | −8.95% | +6.86% | 213.2% |
| 4 | 5 | −2.63% | −11.07% | +8.44% | 207.2% |
| 5 | 6 | −3.12% | −13.59% | **+10.47%** | 198.9% |

### 3.3 事前判定の抜け穴

band 5 の正味 +10.47% は「正味 ≥ +10% → SOTA 改善と書ける」を形式上満たす。**が、これは見かけである。**

**生の列が全設定で負であり、band を広げるほど悪化する**（−2.04% → −3.12%）。
正味が上がるのは対照がそれ以上に壊れるからにすぎない（−3.23% → −13.59%）。
帯を広げれば、輪郭を誤った位置に置いた対照は大量の正しい構造を捨てる。
正味 ＝ 生 − 対照 は **2 つの損害の差**であって改善ではない。

| | 生（ベースラインに勝つか） | 正味 |
|---|---:|---:|
| Lotus v1 | **+10.31%**（実際に勝っている） | +18.35% |
| Marigold V2 | **−1.90%（最良設定）** | +4.32% |

**Marigold V2 では、どの有効な設定でも鋭化はベースラインを一度も上回らない。**

事前基準は「正味が実際の改善を追う」前提で書いたが、それが成り立つのは生が正のときだけだった。
v1 では成り立ち、Marigold V2 では成り立たない。
**基準の文言に従えば「続行」だが、中身に従えば「転移しなかった」が正しい。**

### 3.4 外れた予測（記録）

掃引前に 2 つ予測し、2 つとも外した。

- 「`band_px=1` が `band_px=2` を上回る」→ **逆**（+1.18% < +4.32%）
- 「band 1 なら radius 1〜2 で足りる」→ **radius 1 は不足**（`radius > band` が必要）

### テストで見つかった落とし穴

disparity aligner に log depth を食わせても**平均相対誤差 3.6% で済む**。
論文の AbsRel 3.6% とほぼ同じ値なので、**「abs_rel が 0.036 ± 0.004 なら合格」という
絶対値ゲートは aligner の誤用を通してしまう。** 判定を「2 つの aligner を比較して
log 版が明確に良いこと」に変更した。テストにも相対比較として固定した。
