# 診断駆動の層配置 — 仮説は成立しなかった

実施: 2026-09-02
ブランチ: `feature/object-depth-aux-loss`
前提: [`global_error_findings.md`](global_error_findings.md) / [`prior_work_survey.md`](prior_work_survey.md)

---

## 0. 検証した仮説

> **UNet の深さは空間スケールに対応するので、粗い層に適応させれば大域成分が、
> 細かい層に適応させれば局所成分が動くはずだ。**

成立すれば「対象領域で壊れている成分を測定し、その成分を担う層だけに適応させる」
という手法（汎用 LoRA より少ない適応で同等以上）が組める、という筋だった。

**結果: 成立しなかった。どの層に適応させても、動くのは大域成分だった。**

---

## 1. 設定

`train_lotus_d.py` に `--lora_target_blocks`（`all` / `global` / `local` / `mid`）を追加。
正規表現で UNet のブロックを絞る。マッチ 0 件なら例外で停止する
（意図せず全層に当たる事故を防ぐため）。

UNet の実測構造（attention の projection 層）:

| ブロック | latent 解像度 | proj 数 | ベース params |
|----------|--------------|---------|---------------|
| `down_blocks.0` / `up_blocks.3` | 最高（96²） | 16 / 24 | 2.5M / 3.8M |
| `down_blocks.1` / `up_blocks.2` | 48² | 16 / 24 | 7.5M / 11.3M |
| `down_blocks.2` / `up_blocks.1` | 24² | 16 / 24 | 24.9M / 37.4M |
| `mid_block` | 最低（12²） | 8 | 12.5M |

**LoRA パラメータ数を揃えた**（差が出たら配置の効果と言えるように）:

| 配置 | 対象 | rank | LoRA params |
|------|------|------|-------------|
| global | mid_block + 24² ブロック | 8 | **0.96M** |
| local | 96² ブロック | 29 | **0.95M** |
| all（参照） | 全 attention | 8 | 1.66M |

学習: Hypersim, 1000 step, LR 1e-5 cosine, warmup 200。評価: NYUv2 654枚, `processing_res=768`。

---

## 2. 結果

### 配置は効く

| 配置 | params | abs_rel | vs baseline |
|------|--------|---------|-------------|
| なし | 0 | **0.05000** | — |
| global | 0.96M | 0.05231 | **−4.63%** |
| local | 0.95M | 0.05627 | **−12.55%** |
| all | 1.66M | 0.05585 | −11.71% |

3 本とも劣化（既知の fine-tune 税）。ただし**同じパラメータ数で global は local の約 1/3 の害**で、
配置が結果を大きく左右することは確認できた。

### しかし成分は分離しない

| 配置 | 全体 | **大域成分** | **局所成分** | より動いた成分 |
|------|------|-------------|-------------|---------------|
| global（粗い層） | −4.51% | **−6.08%** | −2.62% | GLOBAL |
| **local（細かい層）** | −12.91% | **−17.34%** | −7.57% | **GLOBAL** |
| all | −12.11% | −15.92% | −7.51% | GLOBAL |

**高解像度層だけに適応させても、大域成分が 17.3% 悪化し、局所成分は 7.6% しか動かない。**
期待した「粗い層 → 大域、細かい層 → 局所」の対応は成立しない。

---

## 3. 解釈

拡散 UNet は残差接続と skip connection で情報が全層を貫通するため、
**どこを触っても出力全体の低周波構造が変わる**と解釈できる。
着手前に挙げていたリスク（「残差接続で情報が混ざるので、きれいに分離しない恐れ」）が現実化した。

配置が効くこと自体は事実だが、それは「大域成分への影響の**大小**」であって、
**成分を選択的に操作できるわけではない**。したがって
「誤差成分を測定して適応先を決める」という差別化は立たず、
ER-LoRA（2025、深度推定の LoRA 層・rank 選択）が扱う「どの層が壊れやすいか」に還元される。

## 4. 実装上の躓き（2 回の起動失敗）

測定前に 2 回、学習が**起動していないのに起動したと報告した**。記録として残す。

| 試行 | 原因 |
|------|------|
| 1 回目 | Bash 経由の入れ子呼び出しで PowerShell 実行ポリシーがスクリプトをブロック。<br>`-ExecutionPolicy Bypass` が必要だった |
| 2 回目 | `--lora_alpha=($rank * 2)` が PowerShell で 2 引数に分裂し、argparse が失敗 |

**教訓**: バックグラウンド起動は「プロセスが立った」ではなく
**「意図した設定でループに入った」ログを確認するまで完了と見なさない**。
3 回目は `LoRA blocks=... trainable params=...` の出力を待ってから先へ進めた。
